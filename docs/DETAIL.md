# Входящие (dsh-inbox) — подробное описание

Плагин `dsh-inbox` заводит в DeepSeek Harness (DSH) Telegram-бота: сообщения
боту попадают в локальную историю, ассистент их читает и может отвечать, а на
странице плагина есть статус, поле токена, переключатель приёма, список
сообщений и поле ответа. Этот файл — полное руководство для новичка; краткая
версия — в `README.md` плагина.

Версия 0.5.0 (MVP): поддержан только Telegram. Почта — задел на будущее, в этой
версии её нет. Начиная с 0.2.0 бот умеет управлять DSH из разрешённого чата:
список сессий, выбор сессии, отправка задач, создание новой сессии и отмена
текущего хода — через команды `/sessions`, `/use`, `/ask`, `/steer`, `/new`,
`/cancel`. Начиная с 0.3.0 команды не нужно запоминать: бот публикует их в меню
Telegram «/» и показывает сессии кнопками. Начиная с 0.4.0 команды общие для
нескольких устройств: одно устройство слушает Telegram, а выполняет команду
любое — ровно один раз, с ответом в чат; в 0.4.1 роль слушателя можно включить
инструментом `telegram_listen`. В 0.5.0 бот показывает «⏳ Думаю…» и присылает
настоящие ответы из DSH по `turn/end`, получил главное inline-меню с
пагинацией сессий, профиль бота (`setMyName`/описания/кнопка меню), проверку по
`from.id`, запрет групп по умолчанию, владельца, лимиты частоты, обработку
`409`/`429`/`400 message is not modified` и ускоренный цикл очереди. По
умолчанию управлять нельзя никому: пользователь должен быть в белом списке.

## Что это и зачем

DSH живёт на компьютере, а вы часто — в телефоне. Telegram есть почти всегда под
рукой. «Входящие» соединяют их: вы пишете своему боту, DSH забирает сообщение,
ассистент видит его в истории и может ответить — вы получаете ответ в том же
чате Telegram. Всё, что видно на странице плагина, видит и ассистент через
инструменты.

Как это устроено:

1. **Бот.** Вы создаёте отдельный аккаунт Telegram у официального
   [@BotFather](https://t.me/BotFather). Бот — обычный аккаунт, но управлять им
   можно программно.
2. **Токен.** BotFather выдаёт строку вида `123456789:AAH…`. Это пароль бота:
   кто знает токен, тот читает входящие и пишет от имени бота.
3. **Хранилище секретов DSH.** Токен сохраняется не в настройках плагина, а в
   сейфе DSH — ссылка `refs.TELEGRAM_BOT_TOKEN`. Хост читает его на каждую
   операцию; в браузер, в конфигурацию и в файл истории он не попадает.
4. **Long polling.** DSH сам спрашивает Telegram `getUpdates` с окном до 25
   секунд. Публичный адрес, домен и сертификат не нужны. После ответа DSH
   запоминает `offset` — номер последнего обработанного обновления — и в
   следующий раз просит только новое.
5. **История.** Сообщения складываются в `~/.dsh/dsh-inbox/state.json` на этом
   компьютере, последние 200 штук. Ответы, отправленные из DSH или ассистентом,
   тоже записываются туда с направлением «исходящее».

Термины простыми словами:

- **@BotFather** — официальный бот Telegram для создания ботов;
- **username** — короткое имя бота, по нему ссылка `t.me/<username>`;
- **токен** — пароль бота для программного доступа;
- **long polling** — DSH ждёт новые сообщения запросом к Telegram, без вебхука;
- **offset** — номер последнего обработанного обновления; хранится, чтобы не
  получать одно и то же дважды;
- **credential store** — сейф DSH для токенов (`refs.*`);
- **MVP** — минимальная рабочая версия.

Зачем это нужно, если есть обычный Telegram: ассистент не просто пересылает
сообщения, а может их обработать — прочитать файлы, запустить тесты, сделать
коммит (другими плагинами DSH) и ответить результатом. «Входящие» — это канал
связи с агентом из телефона.

## Как открыть

Экран настроек один и тот же, путей два.

1. Левая панель DSH → строка **«Входящие»** (📥): открывается только страница
   настроек плагина, без блоков плагин-менеджера («Описание», «Источник»,
   «Версия»).
2. Левая панель DSH → **«Плагины»** (в старых версиях раздел мог называться
   «Настройки → Плагины») → карточка **«Входящие»** (пакет `dsh-inbox`) →
   страница плагина.
3. Сверху вы увидите статус (✅ подключён @bot или ⚠️ токен не сохранён) и
   пометку приёма (включён/выключен).
4. Блок **«Токен бота»**: маскированное поле, кнопки «Сохранить», «Удалить
   токен» (если токен уже есть) и «Проверить», строка «Хранится в хранилище
   секретов DSH…».
5. Блок **«Принимать сообщения»**: переключатель и кнопка «Включить» /
   «Выключить», пояснение.
6. Блок **«Последние сообщения»**: счётчик «в истории: N из 200», кнопка
   «Очистить историю», сам список и поле **«Ответ»** с кнопкой «Отправить».
7. Блок **«Как начать»** — короткая инструкция и ссылка на @BotFather; в конце
   страницы — **«Подробности»** (этот документ).

**Закрепление панели.** Строку в левой панели можно открепить: тогда она уходит
в меню **«Ещё»**, откуда её закрепляют обратно, и левая панель обновляется без
перезагрузки. Видимость и закрепление ведёт **dsh-polish**: состояние лежит в
`localStorage` под ключом `dsh-polish:panel-visibility`
(`{visible: string[], pinned: string[]}`), а об изменениях dsh-polish сообщает
событием `dsh-polish:panels-changed`. main-панель плагина регистрируется всегда,
строка `sidebar.panellist` — только пока панель закреплена.

Токен вводится только здесь. В общем чате DSH и в отдельном чате Telegram токен
вводить не нужно и небезопасно.

## Как пользоваться пошагово

### Шаг 1. Создайте бота у @BotFather

1. В Telegram откройте [@BotFather](https://t.me/BotFather) — у официального
   бота синяя галочка. В поиске приложения наберите `BotFather`.
2. Отправьте **`/newbot`**.
3. Введите **имя бота** — отображаемое имя, например `Мои входящие`. Это имя
   можно потом поменять командой `/setname`.
4. Введите **username** — латиница, цифры и подчёркивания, обязательно
   заканчивается на `bot` (например, `moy_vhodnye_bot`). Если username занят,
   BotFather попросит другой.
5. BotFather пришлёт сообщение «Use this token to access the HTTP API» и строку
   вида `123456789:AAH…`. Скопируйте её **целиком**, включая цифры до двоеточия.
6. Проверить бота: откройте `t.me/<username>` и нажмите «Start» (или отправьте
   `/start`). Это создаёт чат с ботом.
7. Если токен потерян или утёк: `/mybots` → выберите бота → **API Token** →
   **Revoke current token**. Старый токен сразу перестанет работать; новый
   вставьте в DSH.

Дополнительно (необязательно):

- `/setdescription` и `/setabouttext` — описание бота;
- `/setuserpic` — аватар;
- `/setprivacy` → **Disable** — если хотите, чтобы в группах бот видел все
  сообщения, а не только команды и упоминания. В личных чатах это не нужно:
  там бот видит всё всегда.

### Шаг 2. Сохраните токен в DSH

1. **«Плагины» → «Входящие»** → поле **«Токен бота»**.
2. Вставьте токен и нажмите **«Сохранить»**. Появится «Сохранено. Действует
   сразу, перезапуск не нужен».
3. Плагин сразу проверит токен запросом `getMe` и покажет имя бота. Поле
   маскированное — сохранённое значение не отображается.
4. Заменить токен: ввести новый и сохранить. Удалить: кнопка **«Удалить
   токен»** — токен стирается из хранилища и приём выключается.
5. Если хранилище секретов в профиле доступно только для чтения, появится
   предупреждение: владелец профиля может вписать `refs.TELEGRAM_BOT_TOKEN` в
   `~/.dsh/.credentials.yaml` вручную — файл отслеживается, значение подхватится
   без перезапуска.

### Шаг 3. Проверьте токен

1. Нажмите **«Проверить»**.
2. Вердикты:
   - **✅ бот на связи** — токен принят, рядом имя `@…`, статус стал
     «✅ подключён @…»;
   - **🔴 Telegram отклонил токен** — токен неверный или отозван;
   - **🟡 Telegram не ответил** — сеть, прокси или сбой Telegram;
   - **⚪ токен не сохранён** — сначала сохраните токен.
3. Проверка ничего не меняет в Telegram: это один запрос `getMe`.

### Шаг 4. Включите приём и напишите боту

1. Включите **«Принимать сообщения»** (переключатель или кнопка **«Включить»**).
   Пометка приёма станет «приём включён». Настройка сохраняется в файле
   состояния: после перезапуска DSH приём включится сам.
2. Откройте бота в Telegram и отправьте любое сообщение, например «Привет».
3. Через несколько секунд оно появится в **«Последние сообщения»** со стрелкой
   ⬅, названием чата, временем и текстом.
4. Сообщения приходят только пока DSH запущен и приём включён. Пока DSH был
   выключен, Telegram хранит обновления ограниченное время (до 24 часов); то,
   что сохранилось, DSH заберёт при следующем старте.
5. Сообщения из групп: бот по умолчанию видит только команды и упоминания.
   Либо упоминайте бота через `@username`, либо отключите приватность в
   @BotFather (`/setprivacy` → Disable).

### Шаг 5. Ответьте из DSH

1. В блоке сообщений есть поле **«Ответ»** и кнопка **«Отправить»**. Ответ
   уходит в **последний чат, из которого писали боту** (в группах — в ту же
   группу).
2. Отправленное появится в списке со стрелкой ➡ и подписью «исходящее».
3. Так же можно ответить через ассистента: сформулируйте просьбу в чате DSH.
   Ассистент вызовет `telegram_send`; `chatId` можно указать явно, если нужно
   ответить не в последний чат.

### Шаг 6. Очистка истории

Кнопка **«Очистить историю»** удаляет сообщения только из локальной истории
DSH. В Telegram они остаются. Токен, приём и offset при этом не меняются; новые
сообщения продолжат приходить.

## Белый список

Бот — это удалённое управление всем DSH. Поэтому действует правило: **пока чат
не добавлен в белый список, управлять нельзя никому**. Пустой список — это не
«разрешено всем», а «запрещено всем».

**Как добавить чат.**

1. **«Плагины» → «Входящие»** → блок **«Белый список»**.
2. Напишите chatId через запятую, например `123456789` или
   `123456789, -1001234567890`, и нажмите **«Сохранить список»**.
3. Либо нажмите **«Разрешить этот чат»** в блоке **«Чаты в истории»** — он
   появляется у чатов, которых нет в списке. Уже разрешённые чаты помечены
   бейджем.
4. Ассистенту доступен инструмент `telegram_allow` с параметром `chatId`;
   `telegram_allowed` показывает текущий список.

Где взять chatId: он написан рядом с названием чата в блоке «Чаты в истории»
(и в `telegram_messages`/`/status`). Личные чаты — положительные числа, группы и
каналы — отрицательные (`-100…`).

**Что происходит с чужим чатом.**

- команды не выполняются;
- сообщение сохраняется в истории с пометкой **«⛔ нет доступа»**, чтобы вы
  увидели чат на странице и могли его разрешить;
- бот отвечает **«⛔ Нет доступа. Попросите владельца DSH добавить этот чат в
  белый список.»** — не чаще одного раза в 5 минут на чат, чтобы чужой чат не
  мог засыпать бота сообщениями;
- ответ на такое сообщение в историю не записывается: истории нужны для работы,
  а не для переписки с посторонними.

**Подтверждения.** На каждое обработанное сообщение из разрешённого чата бот
отвечает:

- **«✅ Принято: …»** — и коротко, что именно сделано: «сообщение поставлено в
  очередь сессии «Отчёт»», «создана сессия abc12345…», «текущая сессия:
  «Отчёт»»;
- **«⚠️ Не выполнено: <причина>»** — если команда не сработала: сессия не
  выбрана, DSH не нашёл сессию, нет сервиса `sessionController` и т. п.

Ответы записываются в историю как исходящие сообщения, поэтому их видно и на
странице плагина.

## Управление сессиями

«Сессия» — открытый разговор с ассистентом в DSH: то, что вы видите в списке
сессий интерфейса. Бот работает с сессиями через штатный сервис DSH
`sessionController` (Web/Desktop). Если профиль его не предоставляет, команды
честно ответят «⚠️ Не выполнено: сервис sessionController не найден…».

**Порядок работы.**

1. В разрешённом чате: **`/sessions`**. Бот пришлёт до 10 последних сессий DSH
   (субагенты исключены): номер, название, «выполняется» или «ожидает».
2. **`/use N`** — выбрать сессию номер N для этого чата. Выбор сохраняется в
   `~/.dsh/dsh-inbox/state.json` и переживает перезапуск DSH. Его видно на
   странице плагина в блоке «Текущая сессия для чата».
3. **`/ask <текст>`** — поставить сообщение в очередь выбранной сессии. Обычный
   текст без команды работает так же.
4. **`/steer <текст>`** — вклинить сообщение в текущий ход (если сессия уже
   выполняется).
5. **`/new <текст>`** — создать новую сессию, отправить в неё текст и сделать её
   текущей для чата.
6. **`/cancel`** — отменить текущий ход выбранной сессии.
7. **`/status`** — состояние бота (приём, история, последняя ошибка), белый
   список и текущая сессия. **`/last`** — последние 5 сообщений истории
   «Входящих» (не сессии). **`/help`** — шпаргалка.
8. **«Сбросить»** в блоке «Текущая сессия для чата» отвязывает сессию от чата,
   не удаляя саму сессию.

**Ограничения управления.**

- Бот отправляет только текст; вложения и картинки не поддерживаются.
- Бот не меняет модель, пресет и настройки сессии — только очередь, steer,
  создание и отмену.
- Субагенты не показываются в `/sessions` и не выбираются: ими управляет
  родительская сессия.
- Если сессию удерживает другой писатель (открыта на запись в другом окне DSH),
  бот попросит закрыть её там.
- `resolveAgent` открывает или возобновляет сессию; на холодной сессии это
  может занять секунду.

## Команды бота

| Команда | Что делает |
| --- | --- |
| `/help` | шпаргалка по командам |
| `/status` | состояние бота, белого списка и текущей сессии |
| `/sessions` | 10 последних сессий DSH: номер, название, состояние |
| `/use N` | выбрать сессию номер N для этого чата |
| `/ask <текст>` | поставить сообщение в очередь текущей сессии |
| `/steer <текст>` | вклинить сообщение в текущий ход |
| `/new <текст>` | создать новую сессию и отправить в неё текст |
| `/cancel` | отменить текущий ход текущей сессии |
| `/last` | последние 5 сообщений истории «Входящих» |
| обычный текст | то же, что `/ask` в текущую сессию |

Форма `/команда@имя_бота` тоже работает — это удобно в группах, где бот получает
только команды и упоминания. Регистр команды не важен: `/HELP` = `/help`.

## Меню Telegram

Команды не обязательно помнить наизусть: у бота есть три уровня нативного меню.

**1. Список команд в «/».** Telegram показывает его, если нажать «/» в поле
ввода. Бот публикует список через `setMyCommands` (scope `default`) после
успешной проверки токена и при запуске DSH с включённым приёмом:

| Команда | Описание в меню |
| --- | --- |
| `/help` | Помощь |
| `/status` | Состояние |
| `/sessions` | Сессии |
| `/use` | Выбрать сессию |
| `/ask` | Спросить в сессию |
| `/steer` | Вклиниться |
| `/new` | Новая сессия |
| `/cancel` | Прервать |
| `/last` | Последние входящие |
| `/menu` | Показать меню |

Список кэшируется: повторно он отправляется не чаще раза в сутки, при смене
версии плагина (сейчас 0.5.0) или после неудачной попытки. Ошибка публикации не
влияет на приём сообщений — бот продолжает работать. Принудительно обновить
меню можно кнопкой **«Обновить меню команд»** на странице плагина (блок «Меню в
Telegram»); там же видно, опубликовано ли меню.

**2. Главное inline-меню.** `/start` и `/menu` присылают приветствие с кнопками
**📋 Сессии**, **🆕 Новая сессия**, **ℹ️ Статус**, **⚙️ Настройки**,
**❓ Помощь**. На каждом экране есть кнопка **«🏠 Меню»** — возврат в главное
меню. `/start <sessionId>` (deep link) сразу выбирает указанную сессию, если она
существует.

**3. Экраны сессий и статуса.**

- `/sessions` присылает до **5 сессий текущего проекта** (без пустых и
  субагентов) кнопками; `sessions:<страница>` листает ◀/▶, `refresh:<страница>`
  обновляет, «📂 Все сессии» показывает `/sessions all`. Кнопки хранят только
  короткий номер (`use:<номер>`) — список запоминается за чатом.
- Выбор сессии (`use:<номер>`) заменяет сообщение на «Сессия выбрана: …» с
  кнопками **💬 Писать** (подсказка `/ask`, стиль primary) и **⏹ Стоп**
  (отмена хода, стиль danger), «🔄 Обновить», «🏠 Меню».
- `/status` — состояние бота, приёма и текущей сессии с кнопками **⏹ Стоп**,
  **📋 Сессии**, **🏠 Меню**.
- `/settings` — что настроено: бот, владелец, группы, белый список, проект,
  очередь, и подсказка менять это на странице плагина.
- `/help` — шпаргалка с кнопками «📋 Сессии», «⚙️ Настройки», «🏠 Меню».
- Обновление экранов заменяет то же сообщение (`editMessageText`), поэтому чат
  не засоряется; `400 message is not modified` считается успехом и не создаёт
  дубль. Если сообщение старше 48 часов и Telegram не даёт его изменить, бот
  присылает новое.

**Как это ведёт себя с белым списком.** Меню видят все, кто открыл бота, но
любое нажатие кнопки и любая команда проверяют `from.id` и тип чата **до**
выполнения действия. Чужой пользователь получает подтверждение нажатия
«⛔ Нет доступа.» (и поясняющее сообщение не чаще раза в 5 минут), действие не
выполняется. Если белый список пуст — не работает ни одна кнопка ни у кого.

**Ограничения меню.**

- Меню команд публикуется для всех чатов бота (scope `default`); отдельные
  scope и language_code не используются.
- Тексты кнопок русские, имена команд — латиницей и в нижнем регистре: это
  требование Telegram, кириллические команды бот не принимает.
- На каждое нажатие бот всегда отвечает `answerCallbackQuery` (в том числе на
  устаревшее или чужое) — спиннер на кнопке не зависает; ошибки ответа не
  останавливают приём сообщений.
- Кнопки не отправляют вложения — только текст через `/new`, `/ask`, `/steer`.

## Ответы из DSH

`/ask`, `/steer`, `/new` и обычный текст не только ставят сообщение в сессию, но
и приносят ответ обратно в Telegram.

1. Перед отправкой промпта бот вызывает `sendChatAction: typing` и отправляет
   **«⏳ Думаю…»**.
2. Устройство-исполнитель подписывается на глобальное событие
   `ctx.on('session/event')`, запоминает текст последнего
   `assistant/message` этой сессии и ждёт `turn/end`.
3. На `turn/end` бот редактирует «⏳ Думаю…» в ответ. Длинный ответ режется на
   части по 4096 символов (по границе строки/слова) и уходит несколькими
   сообщениями; первый фрагмент — редактированием, остальные — новыми
   сообщениями.
4. Если за **10 минут** `turn/end` не пришёл, сообщение заменяется на
   **«⚠️ Ответ не получен: DSH не завершил ход за 10 минут.»** Ошибка постановки
   промпта сразу заменяет «Думаю…» на «⚠️ Не выполнено: <причина>».
5. `pendingAsk` хранится в памяти исполнителя: `sessionId → { chatId,
   messageId, startedAt }`. Состояние не пишется на диск, поэтому после
   перезапуска DSH старые «Думаю…» просто остаются без правки (их можно
   перезапросить).
6. Частичный ответ без `turn/end` не показывается: бот ждёт завершения хода,
   чтобы не присылать черновики.

## Профиль бота

Помимо меню команд бот оформляет профиль Telegram:

- **имя** — `📥 DSH Входящие` через `setMyName` (≤64 символа);
- **описание** — что умеет бот, на русском, через `setMyDescription` (≤512);
- **короткое описание** — через `setMyShortDescription` (≤120);
- **кнопка меню** — `setChatMenuButton({ type: 'commands' })`, чтобы у поля
  ввода открывался список команд.

Профиль публикуется после успешной проверки токена, при запуске DSH с
включённым приёмом и по кнопке «Обновить профиль» на странице плагина. Кэш —
24 часа на версию плагина; ошибки Telegram (`setMyName` и т. п.) только пишутся
в лог и не мешают приёму сообщений. Страница показывает имя, описание, команды и
статус публикации.

## Безопасность

- **Проверка по `from.id`.** Белый список (`allowedUserIds`) хранит user id
  отправителя, а не chat id; resolve идёт из каждого сообщения и колбэка.
  Инструмент `telegram_allow` добавляет пользователя; `allowedChatIds`
  сохраняется для совместимости и миграции старых файлов.
- **Личные чаты.** Пока `security.groupsEnabled` не включён в локальном UI,
  сообщения и кнопки из групп (`chat.type !== 'private'`) отклоняются.
- **Владелец.** Первый разрешённый пользователь становится `ownerUserId`/
  `ownerChatId`. Сменить владельца можно только на странице плагина (роут
  `/api/dsh-inbox/security`); инструменты агента этого не умеют.
- **Лимиты.** `RATE_WINDOW_MS = 1500` (одна команда в 1,5 с на чат) и
  `RATE_HOUR_LIMIT = 30` (в час); превышение — вежливое сообщение, действие не
  выполняется. `update_id` дедуплицируются (до 1000 последних): повторный батч
  после неудачного git-пуша не выполнится дважды.
- **409 Conflict.** При запуске опроса Telegram может ответить 409 (webhook или
  второе устройство). Бот останавливает цикл, вызывает `getWebhookInfo`,
  сохраняет URL и объясняет причину; на странице появляется предупреждение и
  кнопка **«Снять webhook»** с подтверждением — она вызывает `deleteWebhook` и
  возобновляет приём.
- **429.** При `retry_after` клиент ждёт указанное время (не больше 60 с) и
  повторяет запрос один раз; повторная 429 возвращается как ошибка.
- **400 not modified.** `editMessageText` с «message is not modified»
  трактуется как успех — дубль не отправляется.
- **Очередь** — at-least-once; приватный репозиторий обязателен, исполнитель
  дополнительно перепроверяет отправителя команды из git локальным белым
  списком перед выполнением.

## Работа с нескольких устройств

Один бот может обслуживать несколько компьютеров с DSH. Правило простое:
**Telegram слушает только одно устройство**, а команду выполняет любое
устройство, которое первым заберёт её из общей очереди. Команда выполняется
ровно один раз, ответ приходит в Telegram от исполнителя.

**Что нужно.**

1. На каждом устройстве — DSH с этим плагином и **токен бота в его сейфе**
   (`refs.TELEGRAM_BOT_TOKEN`): токен нужен каждому, чтобы отправить ответ в
   Telegram. Токен один и тот же (один бот), но хранится на каждом устройстве
   отдельно.
2. Общий git-репозиторий, тот же `remote`, что настроен в **dsh-sync**
   (`~/.dsh/dsh-sync.json`, поле `remote`). Плагин заводит в нём собственную
   ветку `inbox`; зеркало dsh-sync на ветке `main` не затрагивается.
3. **Репозиторий должен быть приватным**: в ветке `inbox` лежат тексты команд,
   ответы, chatId и идентификаторы устройств.
4. На каждом устройстве должен работать `git` и быть доступ к репозиторию (та
   же авторизация, что у dsh-sync).

**Пошагово.**

1. Убедитесь, что dsh-sync настроен на общий репозиторий (в его настройках есть
   remote), и что `git ls-remote <remote>` работает на обоих устройствах.
2. На первом устройстве откройте **«Плагины» → «Входящие» → «Общая очередь»**.
   Блок покажет «настроена», имя и id устройства.
3. Нажмите **«Слушать Telegram здесь»** — это устройство начнёт опрашивать
   Telegram и складывать входящие сообщения и нажатия кнопок в очередь.
   Появится статус «слушает Telegram».
4. На втором устройстве слушателя **не включайте**: оно показывает роль
   «исполнитель». Оно забирает команды из очереди и выполняет их, когда
   выигрывает захват.
5. Отправьте боту команду с любого устройства — её получит слушатель, положит в
   очередь, а выполнит тот, кто первым захватит; ответ придёт в Telegram.
6. В блоке «Общая очередь» видно: счётчики «новых / в работе / готово», кто
   выполняет команду сейчас, список устройств (кто слушает, кто исполнитель),
   время последней синхронизации и последнюю ошибку.
7. **«Синхронизировать сейчас»** — принудительный цикл: забрать очередь и
   выполнить готовые команды, не дожидаясь 1–1,5 секунд.

**Как устроена очередь.**

- Команды — неизменяемые JSON-файлы в ветке `inbox`:
  `inbox/commands/<id>.json`, `inbox/claims/<id>/<device>-aN-<ts>.json`,
  `inbox/results/<id>/<device>-<ts>.json`, `inbox/done/<id>.json`,
  `inbox/status/<device>.json`, `inbox/offset/<device>.json`.
- Каждый апдейт Telegram (сообщение или нажатие кнопки) превращается в команду;
  id команды выводится из `update_id` и id бота, поэтому повторно полученный
  апдейт не создаёт дубль.
- Смещение Telegram (`offset`) сохраняется на устройстве-слушателе только после
  успешной отправки пачки в очередь: при сбое пачка повторится, дубли отсекутся.
- Захват: устройство пишет claim, отправляет, ждёт 3 секунды (0,4 с на одном устройстве), забирает очередь и
  выбирает победителя по (номер попытки, время захвата, id устройства).
  Проигравший не выполняет. Захват живёт 120 секунд; после этого другой
  исполнитель может взять команду. Попыток у устройства до 3.
- Исполнитель записывает result (`status: ok|error`, `output`) и `done`, затем
  отправляет ответ в Telegram своим токеном.
- Статус устройства публикуется в `inbox/status/<device>.json`; страница
  показывает, кто слушает Telegram, а кто просто исполнитель.

**Ограничения.**

- **At-least-once.** Если устройство упало между действием и записью `done`,
  после истечения захвата команда может выполниться повторно. Ответ в Telegram
  отправляется один раз. Для небезопасных действий проверяйте результат.
- **Telegram хранит обновления до 24 часов**; если слушатель был выключен
  дольше, часть сообщений теряется.
- **Один слушатель.** Если включить приём на двух устройствах, Telegram ответит
  второму `409 Conflict`, а команды могут дублироваться.
- **Общая очередь не заменяет dsh-sync**: это отдельная ветка `inbox` в том же
  репозитории; историю сессий она не синхронизирует.
- **Ветка `inbox` растёт** только добавлением файлов; чистить её нужно вручную
  и осторожно (это история команд).
- **Часы устройств** должны быть примерно синхронны: время захвата участвует в
  выборе победителя.
- Если `remote` в dsh-sync не задан, плагин работает в режиме inline: команды
  выполняются на этом же устройстве сразу, без общей очереди.

**Инструмент агенту.** `telegram_queue_status` показывает: настроена ли очередь,
ветку, устройство, роль (слушатель/исполнитель), счётчики, кто выполняет,
список устройств, последнюю синхронизацию и ошибку. `telegram_status` теперь
содержит ту же краткую сводку очереди. Переключать роль можно инструментом
`telegram_listen` с `{ enabled: true|false }` — он идёт тем же путём, что кнопка
на странице: включает/останавливает polling, возвращает актуальную роль и
предупреждает, если слушатель уже включён на другом устройстве (409). Без
настроенного `remote` инструмент отвечает понятной ошибкой «Общая очередь не
настроена…».

## Примеры

**Инструменты ассистента.**

| Инструмент | Параметры | Меняет данные? | Что делает |
| --- | --- | --- | --- |
| `telegram_status` | — | нет | токен сохранён или нет, имя бота, включён ли приём, последняя ошибка, история, белый список, текущая сессия |
| `telegram_messages` | `limit` (по умолчанию 10, максимум 50) | нет | печатает последние сообщения: направление, время (UTC), отправитель, чат, текст |
| `telegram_send` | `text` (обязателен, до 4096 символов), `chatId` (id или `"last"`, можно не указывать) | **да** | отправляет сообщение через бота и записывает его в историю |
| `telegram_allowed` | — | нет | показывает белый список чатов, которым разрешено управлять DSH |
| `telegram_allow` | `chatId` (обязателен) | **да** | добавляет чат в белый список |
| `telegram_queue_status` | — | нет | состояние общей очереди: устройство, роль, счётчики, устройства, последняя синхронизация и ошибка |
| `telegram_listen` | `enabled` (обязателен, boolean) | **да** | включает/выключает роль «Слушать Telegram здесь»: запускает или останавливает опрос, возвращает роль и предупреждение про 409 |

**Примеры фраз агенту:**

- «Покажи, что пришло в Telegram» — `telegram_messages`.
- «Покажи белый список бота» — `telegram_allowed`.
- «Разреши чат 123456789 в боте» — `telegram_allow`.
- «Ответь в Telegram: отчёт будет к 18:00» — `telegram_send` в последний чат.
- «Проверь, работает ли бот» — `telegram_status`.

**Примеры команд в Telegram** (из разрешённого чата):

```text
/sessions
# ✅ Принято: сессий: 3
# 1. Отчёт по тестам — выполняется
# 2. Ревью изменений — ожидает
# 3. Новая сессия — ожидает
# Сессии текущего проекта (3) — страница 1 из 1. Выберите кнопкой или /use N.

/use 1
# ✅ Принято: текущая сессия: «Отчёт по тестам» (abc12345…)

/ask проверь сборку и напиши итог
# ⏳ Думаю…           (через несколько секунд это же сообщение станет ответом)
# ✅ Готово: сборка прошла, 182 теста зелёные.

/new начни новую задачу: обнови README
# ⏳ Думаю…           (затем — ответ из новой сессии DSH)

/cancel
# ✅ Принято: отмена запрошена для сессии «…»
```

**Пример вывода `telegram_messages`:**

```text
Последние сообщения (2 из 2), время в UTC:
1) ⬅ входящее · 2026-11-22 10:00 · Иван · чат «Иван»: Привет, DSH
2) ➡ исходящее · 2026-11-22 10:02 · DSH · чат «Иван»: Привет! На связи.
```

**Пример вывода `telegram_status`:**

```text
Входящие (Telegram): токен сохранён.
Бот: @moy_vhodnye_bot
Приём сообщений: включён
Последняя ошибка: нет
История: 2 сообщений (максимум 200, время в UTC).
Последний чат: «Иван» (chatId 555).
```

**Пример вывода `telegram_send`:**

```text
Отправлено в «Иван» (chatId 555), message_id 42.
```

## Что вы увидите

**Статус вверху страницы.**

| Статус | Значение |
| --- | --- |
| ✅ подключён @bot | токен сохранён и проверен, Telegram отвечает именем бота |
| ✅ подключён (без имени) | токен сохранён, но `getMe` ещё не выполнялся — нажмите «Проверить» |
| ⚠️ токен не сохранён | в хранилище секретов пусто |
| приём включён | long polling работает |
| приём выключен | DSH не спрашивает Telegram о новых сообщениях |

**Вердикты проверки:** ✅ бот на связи; 🔴 Telegram отклонил токен; 🟡 Telegram
не ответил; ⚪ токен не сохранён; «ещё не проверялся» — до первой проверки.
Проверка идёт один-два запроса, в браузер токен не передаётся.

**Строка «Последняя ошибка»** под заголовком: «нет» или причина (например,
«токен не принят», «Telegram ограничил частоту запросов (429)»). Ошибки
приёма не ломают страницу: последняя ошибка просто остаётся в строке.

**Список сообщений** — новые сверху. У каждого: стрелка направления
(⬅ входящее / ➡ исходящее), название чата, время (локальное) и текст. Над
списком — «в истории: N из 200» и кнопка очистки. Пустая история подсказывает,
что включить приём и написать боту.

**Поле ответа** — текст уходит в последний чат; кнопка «Отправить». Пока идёт
запрос, кнопки показывают «Отправляем…» / «Сохраняем…» и не висят в
«Выполняется…» навсегда: любая операция заканчивается результатом или ошибкой.

**Страница обновляется сама** каждые 4 секунды, пока открыта; при уходе со
страницы таймер снимается. Поэтому новые сообщения появляются без перезагрузки.

**Блок «Белый список».** Textarea с chatId через запятую, кнопка «Сохранить
список», счётчик «Чатов в списке: N», предупреждение «Список пуст: управлять
DSH из Telegram нельзя никому», подсказка и чипсы чатов из истории. У
разрешённого чата бейдж «разрешён», у остальных — кнопка «Разрешить этот чат».

**Блок «Текущая сессия для чата».** Название сессии, короткий id, состояние
«выполняется» или «ожидает», название чата и кнопка «Сбросить». Пока сессия не
выбрана — надпись «не выбрана» и подсказка: `/sessions`, затем `/use N`.

**Блок «Команды бота».** Шпаргалка: `/help`, `/status`, `/settings`, `/sessions`,
`/use N`, `/ask`, `/steer`, `/new`, `/cancel`, `/last` и правило «обычный текст =
/ask».

**Блок «Меню в Telegram».** Статус «меню команд опубликовано» / «ещё не
опубликовано», дата последней публикации, список команд и кнопка **«Обновить
меню команд»** (принудительный `setMyCommands`).

**Блок «Профиль бота».** Имя, описание, короткое описание, список команд,
статус публикации и кнопка **«Обновить профиль»** (`setMyName`,
`setMyDescription`, `setMyShortDescription`, `setChatMenuButton`).

**Блок «Безопасность».** Владелец (`ownerUserId` + чат), подсказка «менять
только здесь», переключатель «Разрешить/Запретить группы» и предупреждение о
том, что группа даёт доступ каждому участнику; здесь же счётчик ожидающих
ответов DSH.

**Блок «Общая очередь».** Имя и id устройства, статус «настроена / не
настроена», роль «слушает Telegram» или «исполнитель», кнопки «Слушать Telegram
здесь» и «Синхронизировать сейчас», счётчики «новых / в работе / готово», кто
выполняет команду сейчас, список устройств, время последней синхронизации и
ошибка. Если очередь не настроена, блок объясняет режим inline и просит
заполнить `remote` в `~/.dsh/dsh-sync.json`.

**В истории** сообщение из чата вне белого списка помечено бейджем
**«⛔ нет доступа»** и не имеет ответа-подтверждения.

**В списке плагинов** — бейдж «✅ подключён @…» либо «⚠️ токен не сохранён» и
пометка приёма.

**Внешний вид.** Страница центрирована: контейнер до 960 px, отступы 24/28/40 px,
сверху квадрат 52×52 с 📥, заголовок 20 px, подпись в две строки, статус-чипы с
точками и кнопка «Обновить» (маленький вариант — 32 px). Каждая карточка-секция —
фон слоя 1, рамка слоя 2, радиус 14 px, padding 16 px, акцентная полоска 3×14 px
слева от заголовка. Кнопки — единая система (`.tools/plugin-design-spec-v2.md`):
высота 36 px (в шапке 32, в чипах 28), `padding: 0 14px`, радиус 10, шрифт
600 12.5, ширина по тексту. Primary — мягкая заливка brand 18%, рамка brand 55%,
текст brand; secondary — прозрачный фон с рамкой `border-l4`; danger — мягкая
красная заливка. Белый фон с белым текстом запрещён: в тёмной теме brand белый,
поэтому старая сплошная заливка `brand-primary` + `#fff` не читалась. Поля
ввода — 34 px и радиус 9 px, без фиксированных ширин; строки истории и списков
подсвечиваются при наведении. Длинные строки переносятся (`overflow-wrap`), на
900 px шапка становится компактной, на 640 px поля 16 px и кнопки могут
растягиваться на всю строку.

## Частые ошибки и что делать

| Симптом | Причина | Что сделать |
| --- | --- | --- |

| Кнопки не реагируют | приём выключен, DSH не запущен или чат не в белом списке | включить приём, проверить белый список и «Последняя ошибка» |

| Команда выполнилась дважды | обрыв между действием и `done` (at-least-once) | проверять результат небезопасных команд вручную |
| Очередь не синхронизируется | нет доступа к git remote, неверная авторизация | проверить `git ls-remote <remote>` и «Последняя ошибка» в блоке очереди |
| Инструмент не появился после обновления плагина | в запущенном DSH остались регистрации прошлой версии; перезагрузите плагин/DSH | в 0.4.1 регистрации инструментов снимаются при выгрузке плагина: обновите плагин и перезапустите DSH |

## Ограничения и безопасность

**Сеть и данные.**

- Единственный сетевой адрес — `https://api.telegram.org`. Плагин не ходит в
  другие места и не запускает внешние программы.
- Нужен интернет. Без него работает только просмотр уже сохранённой истории.
- История лежит в `~/.dsh/dsh-inbox/state.json` — обычный JSON, последние 200
  сообщений. Она не синхронизируется между компьютерами и не заменяет чат
  Telegram.
- Telegram отдаёт накопленные обновления ограниченное время (по документации
  Bot API — до 24 часов) и только одному потребителю. Если DSH был выключен
  дольше или этого бота опрашивает другая программа, часть сообщений может
  потеряться. Один токен — один потребитель.
- `offset` сохраняется, поэтому уже полученные сообщения не дублируются.

**Токен.**

- Хранится в credential store DSH под именем `refs.TELEGRAM_BOT_TOKEN`
  (`~/.dsh/.credentials.yaml`). В настройки плагина, в файл истории и в браузер
  не попадает: страница получает только «настроен/не настроен», имя бота и
  историю.
- Токен даёт полный доступ к боту: кто его знает, тот читает все сообщения бота
  и пишет от его имени. Не публикуйте токен в чатах, скриншотах и репозиториях;
  при утечке сразу отзывайте у @BotFather.
- Токен читается на каждую операцию: замена или удаление действуют сразу, без
  перезапуска DSH.
- Диагностические сообщения очищаются от токена: вместо значения печатается
  `<токен скрыт>`.

**Поведение приёма.**

- При `401` (токен не принят) приём останавливается, переключатель выключается,
  в «Последней ошибке» появляется «токен не принят». Исправьте токен и включите
  приём снова.
- После сетевой ошибки пауза растёт: 1 с, 2 с, 4 с … до 30 с, затем опрос
  продолжается с новыми попытками.
- Пока токен не сохранён, приём ждёт и повторяет проверку; как только токен
  появится, сообщения начнут приходить без перезапуска.

**Управление DSH.**

- Разрешённый чат получает **полный доступ к управлению DSH**: список сессий,
  выбор любой сессии, отправка задач, создание сессии, отмена хода. Считайте бота
  вторым пультом от компьютера: кто управляет ботом, тот управляет DSH.
- Поэтому белый список пуст по умолчанию, а добавлять в него нужно только свои
  доверенные чаты. Не давайте посторонним доступ к боту и не пересылайте им
  сообщения из него.
- Чужой чат получает отказ **не чаще одного раза в 5 минут**; его сообщения
  видны в истории с пометкой «⛔ нет доступа», команды не выполняются.
- Удаление чата из белого списка сразу отвязывает от него выбранную сессию.
- Бот не удаляет сессии и не меняет их настройки; `/cancel` только отменяет
  текущий ход.

**Ограничения MVP.**

- Почты и других каналов нет — только Telegram.
- Нет отметок «прочитано», папок, поиска и вложений: хранится текст и подпись к
  медиа, остальное пропускается.
- Нет отправки файлов и фото; только текст до 4096 символов.
- Плагин не является официальным продуктом Telegram или DeepSeek.

**Приватность.** Сообщения хранятся только на этом компьютере в истории DSH.
Удалить их можно кнопкой «Очистить историю» или вручную, удалив файл
`~/.dsh/dsh-inbox/state.json` при остановленном DSH.

## Связанные плагины

- **dsh-notify** — уведомления о завершении длинных задач в интерфейсе DSH;
  вместе с «Входящими» удобно, когда работа идёт, пока вы в Telegram.
- **dsh-vault** — зашифрованный сейф: хранит и переносит токены (`refs.*`),
  включая `TELEGRAM_BOT_TOKEN`, между компьютерами.
- **dsh-github-safe** — GitHub-инструменты с подтверждениями; пригодится, если
  из Telegram нужно инициировать действия с репозиторием.
- **dsh-review** — просмотр изменений, тесты, коммит, push и PR из DSH: можно
  попросить бота «проверь тесты», а ассистент выполнит работу инструментами
  review и ответит результатом.
- **dsh-sync** — синхронизация истории DSH между устройствами; сама по себе
  «Входящие» не синхронизирует историю Telegram-сообщений.
- **dsh-polish** — оформление интерфейса и состояние панелей левой панели:
  строка «Входящие» видна, пока панель закреплена.

## Установка и проверка

**Установка из папки.** DSH → **«Плагины» → «Добавить плагин»** → выберите папку
`.publish/dsh-inbox`. Если страница плагина не появилась сразу — перезапустите
DSH. После установки в списке плагинов должна быть карточка «Входящие» с
иконкой.

**Проверка тестами** (из папки плагина, Node 22.19+):

```powershell
node --test test/*.test.mjs
node --check index.js
node --check client.js
```

Тесты идут без сети (кроме временного локального git-remote в тестах очереди) и
без настоящего токена: `fetch` подменяется, токены в тестах фиктивные.
Проверяются хранение истории, маршруты, регистрация инструментов, меню Telegram,
белый список и общая очередь: временный bare-репозиторий, два экземпляра
очереди, одновременный захват (ровно один победитель), дедупликация по
`update_id`, протухший захват, `done` без повторного выполнения, счётчики, а
также то, что токен не попадает в ответы и в файлы очереди.

**Живая проверка после установки.**

1. Сохранить реальный токен и нажать «Проверить» — должен появиться вердикт
   «✅ бот на связи» и имя бота.
2. Открыть бота в Telegram, написать что угодно — сначала убедиться, что чат
   отвечает «⛔ Нет доступа» (белый список пуст).
3. Добавить свой чат в блоке «Белый список» (или кнопкой «Разрешить этот чат») и
   включить приём.
4. Отправить `/help` — должен прийти ответ «✅ Принято: справка по командам».
5. Отправить `/menu` — приходит главное inline-меню «📋 Сессии / 🆕 Новая
   сессия / ℹ️ Статус / ⚙️ Настройки / ❓ Помощь» с кнопкой «🏠 Меню» на
   экранах; в меню «/» виден список команд (если нет — «Обновить меню команд»
   на странице плагина).
6. Отправить `/sessions`, нажать кнопку сессии, затем `/ask проверка связи` —
   сначала придёт «⏳ Думаю…», затем это сообщение заменится ответом из DSH; в
   интерфейсе DSH сообщение должно появиться в выбранной сессии. Нажать
   «🏠 Меню» и «⚙️ Настройки» — сообщение должно обновиться.
7. Ответить из поля «Ответ» на странице — сообщение приходит в Telegram.
8. Перезапустить DSH — приём, история, белый список, выбранная сессия и меню
   должны сохраниться.

**Живая проверка в двух окнах (общая очередь).**

1. Оба устройства: dsh-sync настроен на один приватный remote, оба видят его
   (`git ls-remote <remote>`), на каждом в сейфе лежит токен того же бота.
2. Окно A: «Входящие» → «Общая очередь» → «Слушать Telegram здесь». Должно
   появиться «слушает Telegram», счётчики 0.
3. Окно B: плагин тот же, блок очереди показывает «настроена», роль
   «исполнитель», в списке устройств видно A как слушателя. Не включайте
   слушателя в B.
4. Отправьте боту из Telegram `/help`. В обоих окнах счётчики должны пройти
   «новых → в работе → готово», ответ приходит в Telegram один раз.
5. Напишите `/sessions` и нажмите кнопку — команда выполняется на одном из
   устройств (видно «кто выполняет»), в Telegram приходит «Сессия выбрана».
6. Закройте DSH на устройстве, которое выполнило команду, и отправьте ещё одну:
   после истечения 120-секундного захвата её должен выполнить второй участник.
7. Остановите слушателя в A, включите в B: команды продолжают приходить и
   выполняться; если включить в обоих — Telegram ответит 409 Conflict.
8. Нажмите «Синхронизировать сейчас» в B — счётчики и список устройств
   обновятся без ожидания 4-секундного цикла.
9. Проверьте, что в ветке `inbox` общего репозитория нет токена (только
   команды, статусы и offset).

## Панели: контракт регистрации

Оба слота регистрируются в `client.js` в `apply(ctx)`:

| Слот | Регистрация | Когда |
| --- | --- | --- |
| `main` | `ctx.slots.register({name: 'main', key: 'plugin-inbox'}, InboxPanel)` | всегда: клик по строке левой панели показывает только настройки плагина |
| `sidebar.panellist` | `ctx.slots.register({name: 'sidebar.panellist', id: 'plugin-inbox', order: 27, label: () => t('panelLabel')}, PanelIcon)` | только пока панель закреплена (`pinned`) |

`InboxPanel` рендерит тот же компонент, что и `plugins.detail.section`
(`InboxPage`), поэтому блоки «Описание / Источник / Версия» страницы
плагин-менеджера в панель не попадают. Иконка строки — эмодзи 📥
(`PanelIcon`, `data-dsh-inbox-panel-icon`).

Состояние панелей общее и живёт в `localStorage` под ключом
`dsh-polish:panel-visibility` (`{visible: string[], pinned: string[]}`); его
ведёт **dsh-polish**. Плагин читает `pinned` при старте, слушает
`window`-событие `dsh-polish:panels-changed` и после каждого события
перечитывает состояние: закрепление добавляет строку, открепление снимает её
через disposer. Пока ключа нет, панель считается видимой и закреплённой — как
по умолчанию в dsh-polish; откреплённая панель остаётся в меню «Ещё».

Тесты панелей — `test/panels.test.mjs`: страница без блоков плагин-менеджера,
строка только у закреплённой панели, реакция на событие dsh-polish.
